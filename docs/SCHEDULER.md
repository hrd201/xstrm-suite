# 定时扫描

[中文](SCHEDULER.md) | [English](SCHEDULER.en.md)

参考 AutoFilm v2.0.1 的每任务计划结构，在现有 Python 管理服务中实现。每个计划绑定已保存的一个同步源，独立设置时间、扫描模式、重试和执行时限；复用现有 STRM 生成、状态和字幕同步逻辑。

## 页面操作

1. 在“媒体源”添加并保存扫描目录与输出前缀。
2. 打开“定时任务”，填写名称并选择同步源。
3. 选择执行方式：按间隔、每天固定时间或 Cron。
4. 选择最近新增或全部文件；最近新增支持 1–720 小时回看。
5. 勾选自动执行，按需启用成功后通知 Emby 刷新媒体库，然后保存。

保存立即生效，首次等待显示的下一次计划；需要验证时点击“立即运行”。任务列表显示启停状态、下一次时间和最近结果。最近执行记录包含定时与手动任务、重试等待、执行中断和取消。所有显示时间采用北京时间。

停用计划会取消尚未开始的自动任务与自动重试，不会中断已经运行的扫描；仍可手动点击立即运行。删除计划会取消该计划尚未开始的任务，影片、STRM 和历史记录保留。同步源目录或输出前缀改变后，旧计划显示源已变更，须重新选择源后保存。

## 时间格式

- 间隔：1–43200 分钟，从首次保存或重新启用起计算；重启保留未来时间，迟到的周期合并，不逐一补跑。
- 每天：北京时间 HH:MM。
- Cron：5 段为“分 时 日 月 星期”；6 段为“秒 分 时 日 月 星期”，秒须为 0–59 固定值，最快每分钟一次。
- 星期建议写 mon…sun；数字遵循标准 Cron，0 或 7 表示周日。日和星期同时限定时采用标准 Cron 的 OR 规则。
- 不接受年份字段、随机/哈希字段及秒级高频表达式，避免从其他工具导入时静默改变含义。

示例：`0 */6 * * *` 为整点每 6 小时；`0 0 20 * * *` 为每天 20:00:00。按间隔 360 分钟与整点 Cron 不同，页面会显示各自的下一次执行时间。

## 配置与运行状态

计划存于现有 config/strm-sync.yaml 的 scheduled_tasks。source_key 根据源目录和输出前缀生成，无需重新迁移原有媒体源。每条任务包含 id、name、enabled、source_key、timezone、trigger、interval_minutes、daily_time、cron、mode、recent_hours、refresh_emby、max_retries、retry_delay_minutes、timeout_minutes。

队列与历史存于 data/scheduler.sqlite3；管理服务启动后自动恢复。不需要额外 systemd timer 或宿主机 Cron。全局只有一个调度实例和一个执行工作线程，重复触发同一任务合并到已有活动记录。Web 手动扫描和定时任务共用队列，Bash 扫描与忽略操作还通过同一个内核 flock 锁互斥，旧目录锁残留不会阻塞新任务。

每次入队冻结连接、源和输出参数，使用私有配置快照执行，防止扫描过程中改动配置影响正在执行的任务。快照与队列中的凭据在任务终结后清除，API 和页面不返回它们。数据库、配置快照、日志和部署运行目录均不进入源码包。

重启时保留未来计划与历史；过期计划推进到下一次，不回放所有错过的周期。无法确认完成的运行任务标为中断，不自动重复执行。已在等待的单份排队任务可恢复，自动任务停用或修改后会取消尚未执行的旧版本。

失败最多重试 0–3 次，重试间隔 1–120 分钟；锁被其他写入任务占用时继续排队，不消耗失败重试次数。任务超时会终止进程组，释放写入锁。网盘目录不可访问、字幕同步失败均使扫描命令返回失败。通知 Emby 刷新失败时记录为“完成，需留意”，避免重新扫描已经成功的文件。

最近新增扫描仍需要遍历父目录来发现嵌套更新，不代表只请求最近目录。定时任务不执行全量重建，不自动删除原视频。

## API

- GET /api/admin/xstrm/scheduler：计划、同步源选项、队列数量和最近执行记录。
- POST /api/admin/xstrm/scheduler/save：携带 revision 和 job 保存，冲突返回 409。
- POST /api/admin/xstrm/scheduler/delete：携带 revision 和 id 删除计划。
- POST /api/admin/xstrm/scheduler/run：携带 id 立即排队，返回 run_id。
- GET /api/admin/xstrm/task-run?id=...：查询某次执行，供页面准确跟踪排队和完成状态。

沿用管理入口 Basic Auth 和请求校验头；端口与公网暴露范围不变。非 Docker 环境需要安装 requirements.txt 的依赖并提供 Linux flock。

## 验证

2026-11-05：Linux 容器 58 项测试通过，包含计划解析、时区、过期合并、重启恢复、源变更、暂停删除、串行与去重、有限重试、快照脱敏、进程组终止和内核锁释放。

真实网盘单部样片定时触发 3 次成功，跨一次服务重启仍按时执行；立即运行去重、普通手动扫描串行均通过。不存在目录的故障注入执行首次失败后等待 1 分钟重试，第二次失败即终止。临时测试配置已清理，保留验收历史。实际大目录的全量耗时与长期运行仍需持续观察。
